分布式锁从零实现：Redis SETNX + Lua 脚本的原理与避坑

分布式锁是什么？

在单机环境下，线程安全可以用 mutex 或 threading.Lock() 来保证。但在分布式系统（多台机器/多个进程）中，这些工具就失效了——你需要跨进程的锁，这就是分布式锁。

典型场景：

  • 多调度中心，防止同一任务被重复触发（distributed-scheduler 项目）
  • 库存扣减，防止超卖
  • 分布式 ID 生成器，防止 ID 冲突

最简实现：SETNX

Redis 的 SET key value NX 可以在 key 不存在时设置值，返回 1 表示成功（拿到锁），返回 0 表示失败（锁被占用）。

问题一：锁误删（最常见！）

场景：进程 A 拿到锁，处理任务耗时超过锁过期时间，锁自动释放。进程 B 拿到锁（同样的 key）。进程 A 处理完毕，执行 DEL，把进程 B 的锁删了。

解决方案：用 Lua 脚本保证原子性

问题二：锁过期但任务没执行完

场景：锁过期时间设为 10 秒，但任务实际需要 30 秒。10 秒后锁被其他进程拿走，两个进程都在执行同一任务。

解决方案：看门狗（Watchdog）自动续期

💡 注意：Go 语言中没有内置的看门狗机制，需要自行实现或者使用 Redisson Go 客户端。

问题三：Redis 主从切换时的锁丢失

场景：进程 A 在 Master 上加锁，Master 突然宕机，Salve 成为新的 Master，锁数据还没同步过去。进程 B 在新 Master 上加锁成功，两把锁同时存在。

解决方案：

方案 说明 成本
RedLock 向 N 个独立 Redis 实例加锁，超过 N/2+1 成功才算成功 高，需要 5 台 Redis
Zookeeper 利用 ZK 的强一致性和临时节点 中等
接受风险 如果业务允许短暂重复执行，不做处理 低

分布式锁没有完美的解决方案，只有业务可接受的权衡。

面试官：如何实现一个分布式锁？

我：分布式锁的核心思路是利用 Redis 的 SETNX（SET if Not eXists）指令。我会设置一个 key 作为锁，用 UUID 作为 value（用于区分不同进程），并设置过期时间。

释放锁时用 Lua 脚本保证原子性：只有当锁的 value 等于自己的 UUID 时才删除，防止误删别人的锁。

如果任务执行时间不确定，我会实现看门狗机制，每隔 1/3 过期时间自动续期。

关于主从切换的问题，业界有 RedLock 算法（向 5 个独立实例加锁，超过半数成功才算成功），但实现复杂。如果业务允许短暂重复执行，可以直接接受这个风险。

（顺便提到 distributed-scheduler 项目中正是用这套方案解决了多调度中心任务重复触发的问题）

总结

问题 解决方案
锁误删 Lua 脚本原子性检查 value
锁过期但任务未完成 看门狗自动续期
Redis 主从切换丢锁 RedLock（高成本）或接受风险
锁不可重入 value 改为计数器（Redis 支持 Lua 脚本原子递增）

关联项目：distributed-scheduler — 实际应用了分布式锁解决多调度中心冲突问题
